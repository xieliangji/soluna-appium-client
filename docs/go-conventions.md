# soluna-appium-client Go 编码约定

> 文档状态：Active  
> 适用范围：仓库内所有 Go 生产代码与测试代码  
> Go 版本：以根目录 `go.mod` 为准

## 1. 文档职责

本文档只维护本项目需要刻意强调的 Go 编码约定，不重复一般 Go 教程。

以下内容不属于本文档：

- 对象模型和包边界；
- SDK 能力范围与实施状态；
- Appium 命令、ErrorCode 和 Delivery 契约；
- 资源、兼容性、发布、Git 和 Agent 工作流。

这些内容分别以 `docs/architecture.md`、`docs/design.md`、能力矩阵及对应领域文档为准。

## 2. 命名与导出 API

- 使用惯用 Go 命名和既有缩写形式，如 `ID`、`HTTP`、`URL`、`JSON`、`WDA`。
- `xcuitest` 中每个导出函数必须以 `IOS` 开头。
- `uiautomator2` 中每个导出函数必须以 `Android` 开头。
- 上述前缀规则不机械要求所有导出类型和常量重复平台名；包名已经足够明确时保持简洁。
- 一个稳定语义只提供一个公共名称，不增加 `Tap`/`Click` 等同义别名。
- 默认保持类型、函数和 helper 私有，只导出调用方真正需要的接口。
- 所有导出类型、函数、方法和常量必须有简洁的中文 GoDoc。
- Go 标识符使用英文；协议值、operation、JSON 字段和错误文本使用英文。
- GoDoc 描述可观察行为、边界和不确定性，不承诺 Driver 无法保证的结果。
- 不增加没有类型约束、语义增量或明显便利价值的薄 wrapper。

## 3. 函数签名

- 可能等待或执行远端操作的函数，将 `context.Context` 放在第一个参数。
- `error` 始终作为最后一个返回值。
- 多个值共同表达一个概念时，优先定义明确的结果类型。
- 多个位置布尔参数会降低调用点可读性时，使用枚举或小型 options 类型。
- 不为了假设中的未来扩展，给一两个简单参数提前建立 options 类型。
- 公共时长使用 `time.Duration`，协议单位在编码边界转换。
- nil、空值和零值行为不明显时必须写入 GoDoc。
- 普通参数错误返回 error，不依赖 panic。
- 不把 nil context 当作可选值，也不静默替换为 `context.Background()`。

## 4. 类型与零值

- 自然可行时让公共类型零值可用；否则必须能够明确识别无效零状态。
- 稳定且有限的协议集合使用自定义 string/int 类型。
- Driver 或 Plugin 可扩展键值使用开放 map 类型。
- 稳定 Wire Shape 优先使用具名 request/response struct，而不是 `map[string]any`。
- 需要区分“字段缺失”和显式 `0`、`false`、空字符串时，使用指针字段或等价的存在性表示。
- 不用 truthy 风格判断吞掉有意义的零值。
- 合法空集合优先返回非 nil 空 slice。
- 解码或校验失败时不返回部分构造的公共结果，除非 API 明确定义部分进度。

## 5. 所有权与复制

- 不通过返回的 map、slice、`[]byte` 或 `json.RawMessage` 暴露内部可变状态。
- 返回已保存的可变数据前创建独立副本。
- 需要在调用结束后持有调用方可变数据时，先复制再保存。
- 命令不需要本地状态时，不保留请求 Payload 的引用。
- 不增加隐藏的 package-level 可变状态。

## 6. JSON 编解码

- 稳定 Payload 使用 `encoding/json` struct。
- 只有明确开放的扩展数据才使用 `any` 或开放 map。
- 仅当“省略”和“显式零值”语义相同时使用 `omitempty`。
- 协议要求 JSON array 时，将 nil slice 明确编码为空数组。
- `json.Unmarshal` 成功不代表响应有效；必填字段必须继续做存在性和类型校验。
- 有限枚举和数值范围在转换为公共类型前完成校验。
- 需要延后到领域 decoder 处理的值使用 `json.RawMessage`。
- 请求编码和响应解码尽量靠近拥有该 Wire Shape 的行为。
- 不自行增加协议别名、大小写折叠或隐式类型转换。

## 7. Context

- `context.Context` 只用于取消、截止时间和调用链控制。
- 不把 context 保存到长生命周期 struct。
- 不使用 `context.WithValue` 传递业务数据、Driver 参数、Session 状态或 Element 数据。
- 将调用方 context 贯穿整个操作。
- 大型本地解码、复制或流式处理在合理边界检查 context。
- 生产命令路径不得使用 `context.Background()` 或 `context.TODO()` 绕过调用方取消。
- 只有既有设计明确拥有、且设置独立有界超时的清理流程可以脱离原 context。

## 8. Error 处理

- 配置、参数、传输、协议和远端失败通过 error 返回，不使用 panic。
- 使用 `%w` 或项目结构化错误的 Cause 保留底层错误链。
- 使用 `errors.Is` 和 `errors.As`，不匹配错误字符串。
- 映射公共错误时保留原始 Cause。
- 不因为存在 fallback 值就吞掉 error。
- 错误文本保持简洁、事实化且不包含敏感数据。
- 具体 `ErrorCode`、`Operation` 和 `Delivery` 规则以 `docs/error-model.md` 为准。

## 9. 并发

- 共享本地状态使用最小且合适的同步范围保证 race-free。
- 除非约束确实要求且已有说明，不持锁执行网络 I/O、回调或可能阻塞的调用方代码。
- 每个后台 goroutine 都必须有明确 owner、取消路径和退出条件。
- goroutine 不得在没有明确生命周期的情况下越过 Session 或所属对象存活。
- 不创建无界 channel 或队列。
- 并发不能用来掩盖命令顺序；业务级顺序由调用方负责。
- 没有明确收益时优先使用同步代码。

## 10. 文件、包与 Helper

- 文件按行为归属组织，不机械执行“一类型一文件”。
- 不创建无边界的 `utils.go`、`helpers.go` 或 `common.go`。
- 文件名应能说明其拥有的行为。
- helper 默认私有。
- helper 应表达稳定约束或显著减少噪声；只调用一次且会隐藏控制流时不抽取。
- 不为跨子包复用而扩大根包公共 API。
- 少量清晰重复优于隐藏协议流程或耦合无关行为的抽象。
- 生产或测试文件接近约 1000 行时，检查是否包含多个独立行为域；只有边界真实存在时才拆分。
- 注释解释意图、约束或非显而易见原因，不复述代码。
- TODO 必须包含具体阻塞原因，并引用能力 ID、计划项或 issue。

## 11. Go 测试代码

- 公共行为在可行时使用外部测试包验证。
- 只有无法通过公共 API 合理覆盖的私有纯函数或内部状态才使用同包测试。
- 测试名描述被保护的可观察行为或契约。
- Fixture 和断言 helper 使用 `t.Helper`。
- 测试资源使用 `t.Cleanup`。
- 测试必须确定性执行，不能依赖用例顺序。
- 单元测试和协议测试不使用任意 sleep。
- 完整对象相等能给出更清晰失败信息时，优先整体比较。
- 同一控制流、仅输入输出不同的 case 适合 table-driven test。
- 流程、顺序和短路语义在 table 会掩盖行为时保持显式测试。
- 关键测试条件保留在调用点附近，不埋入深层 Fixture。
- 协议覆盖项和真实环境验证要求由设计及命令契约文档维护。

## 12. 格式与维护

- 所有变更 Go 文件必须通过 `gofmt`。
- 缩进、空格和 import 分组交给 `gofmt`。
- 不进行仅产生格式噪声的手工对齐。
- 优先遵循当前行为所属 package 已形成的局部惯例；与本文冲突时以本文为准。
- 构建、测试和完成报告命令由根 `AGENTS.md` 维护。

只有同时满足以下条件的规则才加入本文档：

- 明确属于 Go 代码编写或组织；
- 在本仓库会重复出现；
- 足够稳定；
- 尚未由其他契约文档负责。
